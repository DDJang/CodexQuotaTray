# CodexQuotaTray 产品需求

文档状态：当前只读 MVP 基线

目标平台：Windows 10/11

最后更新：2026-07-18

## 1. 产品定位

CodexQuotaTray 是一个常驻 Windows 系统托盘的轻量应用。它读取本机 Codex App Server 返回的官方额度状态，让用户无需打开 Usage 页面即可查看：

- 当前有哪些额度窗口；
- 每个窗口还剩多少额度；
- 每个窗口何时重置；
- 数据是最新、刷新中、过期、离线还是不可用。

应用不自行估算官方额度，不分析对话或项目内容，也不执行账户写操作。

## 2. 产品原则

- 使用官方 `codex app-server`，不抓取网页、不读取浏览器 Cookie。
- UI 只消费归一化应用状态，不解析原始 JSON-RPC。
- 使用 `windowDurationMins`、`limitId` 和 `limitName` 识别窗口，不假设 `primary` 或 `secondary` 的固定含义。
- 缺失、null、未知或异常字段必须明确显示为不可用，不能静默补成 0 或 100。
- 刷新失败时保留最后一次有效数据，并准确标记 stale/offline。
- 后台保持低 CPU、低内存和低请求频率。
- MVP 始终只读。

## 3. 当前 MVP 范围

### 3.1 额度展示

托盘卡片展示 App Server 实际返回的全部额度窗口。每个有效窗口包含：

- 官方名称或根据时长生成的动态名称；
- 剩余百分比与进度条；
- 本地时区重置时间；
- 距离重置的倒计时。

剩余百分比计算：

```text
remainingPercent = clamp(100 - usedPercent, 0, 100)
```

窗口对象存在但缺少 schema 要求字段时应跳过该窗口并产生匿名诊断，不能 panic。

### 3.2 状态展示

必须清晰区分：

- `fresh`：最近一次读取成功；
- `refreshing`：保留旧数据并显示正在刷新；
- `stale`：15 分钟未成功刷新，继续展示旧数据；
- `offline`：App Server 或 transport 暂时不可用；
- `unauthenticated`：Codex 尚未登录；
- `unavailable`：当前账户模式或响应无法提供 ChatGPT Codex 额度。

API Key 和 Bedrock 模式不得显示虚假的 ChatGPT 套餐额度。

### 3.3 刷新

刷新来源统一进入同一个协调器：

1. 应用启动；
2. 用户手动刷新；
3. `account/rateLimits/updated` 通知；
4. 系统从睡眠恢复；
5. 网络恢复；
6. 卡片打开且数据缺失或至少 60 秒未更新；
7. 无事件时按 Auto、固定 5/15/30 分钟或 ManualOnly 策略调度；所有触发源服从同一单 in-flight 协调器。

任意时刻最多一个 refresh 正在执行；自动、通知和系统事件触发的主动请求最小间隔为 10 秒，用户显式手动刷新在没有 in-flight 时立即执行，失败采用有界退避。

### 3.4 提醒

每个窗口分别支持剩余 50%、20% 和 10% 阈值提醒；提醒使用持久化防重复状态，新启用阈值和首次安装不追溯。

- 首次快照只建立基线，不弹通知；
- 同一窗口、同一周期、同一阈值只提醒一次；
- Windows 安静时段由系统决定，应用不播放声音；
- 用户可关闭提醒。

### 3.5 设置与缓存

- 支持当前用户开机启动；
- 支持显示剩余或已用百分比；
- 可启用/禁用并清除非敏感额度缓存；
- cache 只保存百分比、窗口时长、重置时间、来源 slot、最后成功时间和 CLI 版本；
- 恢复的 cache 一律先标记为 stale，直到实时读取成功。

## 4. 重置次数能力边界

`codex-cli 0.144.5` 已在只读 `account/rateLimits/read` 响应中提供 `rateLimitResetCredits.availableCount` 和可选明细。产品只展示数量与到期摘要；仍不实现、序列化或调用任何重置卡消费方法。

现有 `credits { hasCredits, unlimited, balance }` 是通用 credits 状态，不是重置次数。当前要求是：

- UI 显示“当前服务端暂未提供重置次数”；
- 不把缺失值显示为 0；
- 不从 `credits.balance`、网页、Cookie 或历史数据推断；
- 不提供任何重置消费入口。

只有新版 stable schema 明确提供权威数量、schema diff 与匿名实测一致，并经过单独产品评审后，才能解锁“只读展示数量”。消费操作需要另行威胁建模，不随展示能力自动解锁。

## 5. 非目标

- 预测剩余消息条数或任务消耗；
- 用 Token 数自行换算官方百分比；
- 自动购买 credits 或自动消耗重置；
- 读取/修改 Codex 凭据；
- 自建账户同步服务；
- Electron、WebView 或常驻浏览器；
- 用量历史图、多账户、IDE 插件或桌面悬浮窗。

## 6. UI 要求

### 6.1 托盘图标

图标必须以形状和文字共同表达 normal、caution、critical、exhausted、refreshing、offline，不能只依赖颜色。

### 6.2 悬停摘要

摘要使用实际窗口名称与剩余百分比；数据不可用时显示状态和最后更新时间，不伪造窗口。

### 6.3 单击卡片

卡片按实际窗口数量动态布局，显示状态、额度行、低权重的重置次数能力提示以及刷新/官方 Usage 操作。后台无持续动画，倒计时精确到分钟即可。

## 7. 性能与平台目标

- Windows 10/11 x64；
- 空闲平均 CPU 目标低于整机 0.1%；
- 主进程空闲工作集目标不高于 35 MB；
- 安装内容目标小于 20 MB；
- 不常驻浏览器内核；
- 冷启动后尽快显示托盘与缓存，官方读取异步完成；
- 连续运行不得出现进程、句柄或内存持续增长。

## 8. 隐私与安全

禁止记录或持久化：

- access token、refresh token、Cookie；
- 用户邮箱和完整账户标识；
- 完整 reset-credit 标识；
- 原始认证/额度响应；
- 对话、项目代码或浏览历史。

Codex CLI 负责认证。本应用只通过子进程 stdio 接收响应，原始 JSON 在内存中完成 typed parsing 后丢弃。完整要求见 `PRIVACY.md`。

## 9. 验收标准

- **AC-01 动态窗口**：约 300 分钟显示为 5 小时，约 10080 分钟显示为 7 天，其他时长生成动态名称。
- **AC-02 百分比**：`usedPercent = 28` 显示 72% 剩余；越界输入被 clamp 并产生匿名诊断。
- **AC-03 重置时间**：`resetsAt` 按 Windows 当前时区显示具体时间与倒计时。
- **AC-04 缺失字段**：缺失窗口或字段不显示为 0/100，malformed response 不导致 panic。
- **AC-05 失败保留**：刷新失败保留最后有效快照，15 分钟后转 stale。
- **AC-06 认证隔离**：未登录、API Key、Bedrock 不展示旧 ChatGPT quota。
- **AC-07 提醒去重**：按 `previous > threshold && current <= threshold` 跨过 50%、20% 或 10% 时提醒；同周期 at-most-once，新周期重新激活。
- **AC-08 重置次数**：当前 schema 缺少权威字段时显示 unavailable，不显示 0 次。
- **AC-09 只读安全**：任何 UI 操作都不发送额度重置消费或其他账户写请求。
- **AC-10 资源约束**：后台无高频网络轮询、持续动画或明显空闲 CPU 占用。

## 10. 发布门禁

本地只读 MVP 已完成。公开发布仍需：

- Windows 10 与稳定渠道 Windows 11 验证；
- 100/125/150/200% DPI 和多显示器矩阵；
- 组织控制的代码签名与 provenance；
- 单独安排的七天稳定性测试。

## 11. 0.2.0 验收补充

- 动态 stale：普通模式为 `max(15 分钟, 有效刷新间隔 × 2)`，仅手动模式为 60 分钟，刷新中与最近失败优先显示。
- 提醒语义：只用有效原始 remaining，按 50/20/10 严格跨越并跨重启 at-most-once；首次安装和新启用阈值不追溯。
- ManualOnly：除用户显式刷新外不主动读取，仍可监听并安全合并完整服务端推送。
- 数据删除：默认卸载删除 settings、quota cache 和 alert state；显式保留全部；关闭额度缓存只删除 quota cache。
